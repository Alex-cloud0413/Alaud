# Alaud · 第一版产品边界

2026-10-25 用户确认开始开发；同轮指定产品名 Alaud。

## 场景

5–10 人、一小时以上的线下会议。原有 Plaud 未随身携带、未吸附在手机时容易错过录音。用户已有 iPhone 快捷指令长按按钮开录的习惯。

## 产品形态

手表 / 手机 / Mac 录音 → 同一 iCloud 录音库与本机转写 → 手机 / Mac「待跟进」 → 后续接入 Agent 后台推进。

三端均提供录音入口。会后最关心与本人有关的承诺、交付依赖和待决策事项。身份归属、任务自动提取及 Agent 执行类别尚未定稿；第一版提供可回查的原音、转写和人工跟进，不制造 AI 已执行的状态。

## 核心验收

1. 开始与结束动作明确，锁屏不主动结束录音。
2. 片段先在录音设备落盘，断线保留，重试去重。
3. 音频、同步、转写状态分别可见；缺失片段不能伪装成完整会议。
4. 跟进、备注及修改后的标题不被迟到的 Watch 数据覆盖。
5. 来电等中断保留已录部分和缺口，允许恢复时续录，恢复失败可见。
6. 导出材料保留来源和时间点；是否进行 Agent 操作由后续规则决定。
7. 手机完整保存并验证整场原音后自动清理手表副本；缺片、校验失败、旧版回执或未登记原音均不得触发删除。

8. iPhone / Mac 只在云端完整确认后释放原音；回听、转写、分享可按需恢复。文字编辑能跨端合并，账号变化阻止旧库自动迁移。

## 界面方向

黑白与中性灰。参考本机 Typeless 的留白、细分隔线和黑色主操作，使用独立 Alaud 图标。手机以录音库和待跟进为首页，底部可达的录音入口；Mac 原生侧栏、列表与详情；Watch 聚焦开始、暂停、继续、结束和待同步数量。录音状态同时用文字、计时与触感表达。

## 暂缓：生理变化与对话时间轴

2026-10-25 用户提出在录音中关联心率、呼吸等数据，辅助识别本人重视的话题；核实平台限制后，用户明确决定先不做，等待更合适的方案。本功能未实现、未采集数据，不进入当前开发计划，保留 [研究记录](PHYSIOLOGY-RESEARCH.md)。
