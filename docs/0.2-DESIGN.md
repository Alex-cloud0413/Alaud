# Alaud 0.2：iCloud 录音库与三端界面

2026-10-25 用户提出：统一 iCloud 保存录音，手机与 Mac 按需下载，增加 Mac 端，三端黑白视觉参考本机 Typeless。

## 存储约定

- Watch 先安全交接给 iPhone，沿用整场完整回执后清理。
- iPhone / Mac 使用同一个 `iCloud.com.gaoyiming.alaud` iCloud Drive 容器。原音作为按摘要命名的不可变文件，会议目录及转写/备注/待办作为可合并的追加快照与 head 标记。占用用户自己的 iCloud 配额。
- 上传成功后必须取得逐片云端回执及可发现的完整会议索引，再释放本地原音。断网、配额不足、账号改变、校验不符、正在使用的原音均不清理。
- 本地保留轻量会议索引和待同步修改。播放、转写、导出按需下载并校验；播放/转写期间保留租约，使用后释放。录音和离线模型仍需本地空间，不能宣称零占用。
- 不实现云端永久删除；本轮只清理已确认能从云端恢复的本地音频。所有真实数据仍在用户设备与私人 iCloud 内，不进入开发归档。
- 使用 iCloud Drive，同账号同容器共用录音库，不受 CloudKit 开发/生产数据库分隔。CloudKit 初次实测返回 Server Rejected Request，最终实现未采用该后端；原因未确认。

## 界面约定

已查看本机 Typeless 首页及设置：浅灰侧栏、白色内容区、黑色主操作、细分隔线、克制的圆角与大标题。借用这些排版原则，Alaud 使用自己的图标和内容。

- 全局仅黑、白与中性灰，录音状态通过实心图形、文字、计时和触感区分；警告仍保留明确文字与符号。
- 手机以录音库和待办为入口，明显的开始录音按钮；详情区分跟进、转写、原音及云状态。
- Mac 使用原生侧栏与列表/详情布局，可录音、查看、搜索、编辑跟进及回听同一录音库。
- Watch 保留抬腕即录的单一主操作与等待交接状态，避免功能堆叠。
- 同步状态必须显示真实的等待、上传、云端保存、按需下载和失败状态。

## 验证边界

测试覆盖旧数据迁移、部分上传、错误回执、配额/断网、正在播放/转写的保留、按需恢复、元数据合并和账号隔离。三端编译、签名、真实 iCloud 上传/另一端下载、界面与真实收音分别记录，任何尚未执行的项目不得记为通过。
